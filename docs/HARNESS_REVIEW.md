# Harness Review

Date:
2026-08-13

This review documents the AI engineering harness components required for SafePaste and distinguishes configured controls from controls that were actually executed.

| Component | Location | What it does | Why it exists | Failure/risk addressed | Execution status |
| --- | --- | --- | --- | --- | --- |
| Persistent instruction file | `AGENTS.md` | Defines local-only architecture, privacy invariants, security rules, testing expectations, and ambiguity handling for AI-assisted development. | Keeps repeated AI work aligned with the privacy-first project constraints. | Prevents drift into network calls, persistence, dependency sprawl, test deletion, or rewriting `SPEC_v1.md`. | CONFIGURED and USED as project guidance throughout development. |
| Security-review sub-agent | `.claude/agents/security-reviewer.md` | Defines a security reviewer role and review format for privacy/security regressions. | Makes review expectations concrete and repeatable. | Catches network/persistence risks, unsafe DOM use, credential gaps, dependency introduction, and weakened tests. | CONFIGURED; security-review findings were recorded in `evals/results_v1.md`, `RED_TEAM.md`, `CHANGELOG.md`, and `AI_WORKLOG.md`. |
| Pre-commit hook | `.claude/hooks/pre-commit.sh` | Scans staged SafePaste production/harness files for obvious credential patterns while excluding test/eval/history fixtures. | Provides a lightweight final guard before commits. | Reduces risk of committing accidental production secrets. | ACTUALLY EXECUTED before SafePaste commits. Earlier `grep` and `mktemp` portability failures were real and are recorded; current hook runs successfully. |
| Permission policy | `.claude/settings.json` | Documents actions that require human approval, discouraged behaviors, allowed local commands, and hook location. | Makes boundaries explicit for AI-assisted work. | Prevents silent package installation, external services, destructive operations, persistence, or hook bypass. | CONFIGURED/DOCUMENTED. Runtime enforcement depends on the local AI tool; this file does not prove enforcement by itself. |
| Unit tests | `tests/test-sanitizer.js` | Verifies deterministic sanitizer behavior. | Provides fast regression protection for privacy and false-positive cases. | Prevents reintroducing failures F1 through F8 and credential gaps. | ACTUALLY EXECUTED; final run passed `38/38`. |
| Main eval runner | `evals/run-evals.js` | Runs spec-linked product, privacy/static, accessibility/product-behavior eval cases. | Connects behavior to requirements and stakeholder trade-offs. | Prevents untracked product/spec drift. | ACTUALLY EXECUTED; final run passed `73/73`. |
| Automated exact/property grader | `evals/graders/exact-property-grader.js` | Checks deterministic properties for selected eval cases. | Supports gradeable, repeatable evaluation without external LLMs. | Confirms sensitive values disappear, markers/context remain, and must-preserve cases stay unchanged. | ACTUALLY EXECUTED; final run passed `91/91` property checks across 21 cases. |
| Human rubric | `evals/graders/human-rubric.md` | Applies H1-H5 privacy/usefulness/readability/proportionality/shareability judgments. | Captures human-in-the-loop trade-offs that exact checks cannot settle. | Exposes localhost, version/IP, firmware ambiguity, and toggle-control judgments. | MANUALLY APPLIED by the AI-assisted development evaluator; not an external user study. |
| Product behavior harness | `evals/run-product-behavior.js` | Exercises empty input, clear, copy API call, IPv4 toggle, and large multiline behavior with a mocked DOM. | Verifies product workflows beyond sanitizer unit tests. | Catches stale output, disabled-copy, scoped-toggle, and multiline workflow regressions. | ACTUALLY EXECUTED; final run passed `5/5`. |
| Accessibility static checker | `evals/run-accessibility-checks.js` | Checks labels, button text, checkbox label, semantic HTML, live region, focus CSS, native controls, and text state. | Automates accessibility checks possible without a real browser. | Reduces risk of unlabeled controls or color-only status. | ACTUALLY EXECUTED; final run passed `10/10`; browser keyboard/screen-reader checks remain NOT VERIFIED. |
| Red-team runner | `evals/run-red-team.js` | Runs product red-team cases for credentials, HTML/script-like input, invalid IPs, localhost, Unicode, and repeated secrets. | Preserves adversarial testing evidence. | Detects common privacy and injection-related regressions. | ACTUALLY EXECUTED; final run passed `15/15`. |

Important caveat:
The hook did not block a real production secret during final work. Earlier hook failures were portability failures discovered by manual invocation and smoke testing, not successful secret-blocking events.
